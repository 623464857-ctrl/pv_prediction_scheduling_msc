# Step 9: 多任务学习实验报告

**日期**: 2026-08-10  

---

## 1. 实验目的

**核心问题**：验证多任务学习（MTL）是否能达到单任务基线（Step5）的预测精度。

- **Step5（基线）**：单任务学习，每个预测步长（H1/H4/H16）独立训练模型
- **Step9（本次实验）**：多任务学习，多个预测步长共享编码器联合训练

用户反馈使用多任务预测后，H16的R²系数从单任务基线的0.9106下降至0.8418，降幅达7.55%。本实验旨在：
1. 排查MTL与Step5单任务基线的配置差异
2. 对齐关键配置后重新训练MTL模型
3. 分析MTL在H16上精度下降的根本原因

---

## 2. 实验步骤

### 2.1 配置差异排查

| 组件 | Step5 单任务 | Step9 MTL (原始) | 问题 |
|------|-------------|------------------|------|
| **残差Scaler** | 每个horizon独立拟合 | 所有horizon混合拟合一个scaler | ❌ 归一化基准不一致 |
| **预测方式** | 16步多输出模型 | 1步模型循环调用16次 | ❌ 非真正多步预测 |
| **损失函数** | CombinedV2Loss | CombinedV2Loss | ✅ 已对齐 |
| **模型架构** | CNN-BiLSTM | CNN-BiLSTM | ✅ 已对齐 |

### 2.2 修复方案

创建多步预测版本MTL模型，对齐Step5架构：

```python
class MultitaskMultiStepRegressor(nn.Module):
    def __init__(self, ...):
        self.encoder = CNNBiLSTMEncoder(...)  # 共享编码器
        self.head_H1 = nn.Linear(hidden*2, 1)   # 1步输出
        self.head_H4 = nn.Linear(hidden*2, 4)   # 4步输出
        self.head_H16 = nn.Linear(hidden*2, 16) # 16步输出
```

- 每horizon使用独立的scaler参数
- 使用真正的多输出架构
- 训练参数：max_epochs=50, patience=8, lr=0.001

### 2.3 模型配置对比

| 配置 | 小模型 | 大模型 |
|------|--------|--------|
| Conv Channels | 32 | 64 |
| BiLSTM Hidden | 64 | 128 |
| Layers | 2 | 3 |
| 参数量 | ~100K | ~400K+ |

### 3.2 R²差距汇总

| Model | H1 | H4 | H16 |
|-------|-----|-----|-----|
| **Step5 单任务 (基线)** | **0.9887** | **0.9687** | **0.9106** |
| Step9 MTL 大模型 | 0.9884 | 0.9546 | 0.8418 |
| **差距** | -0.03% | -1.46% | **-7.55%** |

### 3.3 容量增大效果验证

| 模型 | 参数量 | H16 R² | 提升 |
|------|--------|--------|------|
| 小模型 | ~100K | 0.8428 | - |
| 大模型 | ~400K+ | 0.8418 | +0.001 |

**结论**：增大模型容量几乎无效，MTL在H16上精度下降的问题无法通过增加参数解决。

## 4. 原因分析

### 4.1 H1几乎无差距 (-0.03%)

- H1任务简单（15分钟预测），模型容易学习
- 单步预测不需要捕捉长期时序依赖
- 共享编码器对简单任务的影响最小

### 4.2 H4差距约1.5%

- 4步预测增加了时序复杂度
- 共享编码器开始承受多任务冲突
- 仍在可接受范围内

### 4.3 H16差距达7.55% — 根本原因

**核心原因：任务冲突（Task Interference）**

1. **任务难度不匹配**：H16（4小时预测）是最难的任务，需要捕捉长期时序依赖；H1（15分钟）是最简单的任务。共享编码器难以同时满足简单任务和困难任务的需求。

2. **梯度冲突**：多任务学习时，不同任务的梯度方向可能相反。H1的梯度倾向于学习短期模式，H16的梯度倾向于学习长期模式，共享参数被迫在两个方向上"妥协"。

3. **IDWA权重偏向简单任务**：当前的任务权重平衡策略可能不自觉地给简单任务（H1）更高权重，导致困难任务（H16）没有得到足够的训练信号。

4. **长期依赖建模困难**：H16需要模型记忆更长时间跨度的信息，而共享编码器在编码所有任务时，可能优先保留对简单任务有用的短期信息，牺牲了对复杂任务至关重要的长期信息。

### 4.4 为什么增大容量无效？

```
小模型(100K): H16 R² = 0.8428
大模型(400K+): H16 R² = 0.8418
```

**结论**：瓶颈不在于模型容量（Parameters），而在于**任务冲突（Task Conflict）**。增加更多参数只是让模型更好地同时拟合多个任务，而非更好地完成每个任务。

## 5. 结论与建议

### 5.1 主要发现

| 发现 | 说明 |
|------|------|
| MTL配置对齐后差距仍存在 | 问题源于多任务学习架构本身，非配置错误 |
| H16是MTL的主要瓶颈 | 长期预测任务对多任务学习的任务冲突最敏感 |
| 容量增大无效 | 任务冲突是根本原因，单纯增加参数无法解决 |

### 5.2 实际应用建议

| 场景 | 建议 |
|------|------|
| 追求最高精度 | 使用Step5单任务模型 |
| 需要效率/一致性 | MTL是可接受的折中方案（H1/H4影响小） |
| H16长期预测 | **强烈建议使用单任务**，MTL无法达到基线水平 |

### 5.3 进一步优化方向

1. **动态任务权重**：根据任务难度自适应调整IDWA权重，给H16更高权重
2. **渐进式学习**：先训练H1，再逐步加入H4、H16
3. **任务专属适配**：在共享编码器后添加任务特定层（Adapter）
4. **分阶段MTL**：先训练共享编码器，再微调各任务头
